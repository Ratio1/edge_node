Synonym: Values entries may match wording, not just their text ("IP addresses"->indicator_type='ipv4', "CISA KEV"->cisa_kev); add only implied wording.
Entities: groups, APTs, gangs and named intrusion sets are ThreatActor, never Malware; malware families, ransomware, RATs and loaders are Malware; ATT&CK utilities such as Mimikatz are Tool. Malware, ThreatActor and Campaign names are stored lower case; Tool names keep display case. Match a ThreatActor, Malware or Tool by name or alias, case-insensitively: (toLower(n.name) = 'x' OR any(x IN coalesce(n.aliases, []) WHERE toLower(x) = 'x')). Ids are exact: 'CVE-2024-3400', 'T1566.001', 'TA0006'.
Graph rules: Indicator INDICATES CVE means named in the same report, never exploited; only ThreatActor EXPLOITS CVE. Campaign membership is PART_OF_CAMPAIGN. Relationships have no source_id; use the r.sources list ("according to ATT&CK" = 'mitre_attck' IN r.sources). cvss_score is null without CVSS: ranking by it needs IS NOT NULL. Default to `i.active = true` for Indicator and `coalesce(n.deprecated, false) = false` for Malware, Technique, ThreatActor, unless retired or deprecated ones are asked for. Sector questions use (x)-[:TARGETS]->(s:Sector) from the asked entity (Malware, ThreatActor or Indicator). A tactic ("credential access techniques") is (t:Technique)-[:IN_TACTIC]->(:Tactic {mitre_id: 'TA00xx'}). "Used or attributed" malware is (a:ThreatActor)-[:USES_MALWARE|ATTRIBUTED_TO]-(m:Malware). KEV or known-exploited CVEs: c.cisa_exploit_add IS NOT NULL. Excluding sub-techniques is is_subtechnique = false; SUBTECHNIQUE_OF only for parent/child questions.
Never use properties that are not listed: no c.cisa_kev (KEV is c.cisa_exploit_add IS NOT NULL), no active on ThreatActor, Malware or Tool, no first_reported_at. Match a Source by source_id ('threatfox'), never by name. Reach an actor's campaign through the actor: (a:ThreatActor)-[:RUNS]->(c:Campaign), matching the actor by name or alias; never type a campaign name.
Shape: every query ends with LIMIT. "How many" and count questions return one number: RETURN count(DISTINCT x) AS total ORDER BY total DESC LIMIT 1. A question about one property of a named entity (a date, score, name, CWE, products) returns its key and that property: RETURN c.cve_id AS key, c.cwe AS value ORDER BY key LIMIT 1. List questions return the asked entity's key as the first column: RETURN DISTINCT t.mitre_id AS key ORDER BY key LIMIT 50. Investigation/neighbourhood/related-to questions return graph (RETURN p[, q] LIMIT 25). Ranking questions (which of, highest, top, rank, most) return ranked_projection: start MATCH, state the ranking rule given, ORDER BY, always end LIMIT, never collect(). Never return a bare number or property without ORDER BY and LIMIT. After WITH only the listed variables stay in scope: keep every variable a later count or RETURN uses.
Literals: copy IP/CVE values exactly; normalise defanged forms; add only literals given or implied by the wording above.
Temporal: DateTime properties are last_reported_at, first_imported_at, first_seen, last_seen: compare with datetime() - duration('PnD'). CVE published, cisa_exploit_add and cisa_action_due are 'YYYY-MM-DD' strings: compare left(c.published, 10) >= toString(date() - duration('PnD')); this year is left(c.published, 4) = left(toString(date()), 4). No namespaced functions (no date.truncate, no apoc). Indicator last_reported_at is the latest report, first_imported_at when it entered the graph. Rolling windows: past_24_hours/today=P1D; last_week/past_7_days=P7D; last_month/past_30_days/recently=P30D; write durations only as duration('PnD'). A calendar window is the previous calendar period, not rolling. Never invent a temporal property; omit it if none matches.
